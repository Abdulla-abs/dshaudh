# 关卡布局编辑器

双击 `artifacts/关卡布局编辑器.html`，使用 Chrome 或 Edge 打开。文件包含全部脚本与参考图，不依赖网络或额外安装。

画布已与当前游戏边界统一：地形为 60×60 格，绿色边框内才是可建造区域，X、Y 坐标均为 11～48（38×38 格）。建筑的完整占地和每段墙都必须在绿色区域内。属性中的最小坐标会按建筑宽高调整；拖动、画墙、键盘、手填坐标和导入校验均执行同一限制。JSON 中保留 64×64 元数据，仅用于兼容旧格式，不代表可建造范围。

旧版编辑器允许的越界文件现在会被拒绝导入，并保留当前布局。原文件不会被修改；需平移到有效区域后再导入。旧本机草稿若不合新规则，也会保留原存储。更新后请关闭旧页面，重新打开 HTML 文件。

## 自由模式与玩家模式

左侧顶部选择编辑模式。自由模式不受大本营数量和等级配额限制，可以使用原表已有等级自由布局；地图边界和占地仍须有效。

玩家模式按原版规则限制建筑数量和等级，素材栏显示“已放数量／上限”和最高等级。大本营可选 1～10 级，空白布局默认使用本次只读核查的主城等级：8 级（2026-10-19，专用实例 1）。已有大本营时按其等级进入玩家模式；调整等级会同步画布中的大本营。此离线文件不会实时连接账号。

例如，8 级大本营允许日光井和龙银矿各 6 座、龙币库和日光皿各 3 座、龙弹堡 4 座、城墙 200 段且最高 8 级。建筑等级按原版升级链计算，不简单等于大本营等级。玩家陷阱最高 1 级；树石等自然对象只在自由模式放置。详细核查见 [玩家模式证据](../../../analysis/evidence/layout-editor-player-mode.md)。

切换模式、降低大本营等级或导入后，已有超限对象会保留并显示错误。可以删除、降级或提高大本营等级修正，修正后才能导出。普通操作不能新增或加重超限。模式和等级可以撤销，随自动保存和导出文件保留。旧文件默认作为自由模式导入；新建延续当前模式。

玩家模式只约束建筑数量和等级，不模拟建造费用、工人、时间或英雄培养条件。

## 编写布局

1. 左上角填写关卡编号和名称。
2. 选择左侧建筑，再点击格子放置，也可以直接拖入画布。
   “陷阱”分类包含捕兽夹、网兜、蛋壳炸弹，均占 1×1 格，支持 1～10 级。放置后在右侧修改等级，保存和导入导出方式与建筑相同。
   “植物”“石头”“生物”分类包含 29 种原版非商店地图对象，例如柏树、银杏、树桩和花岗岩。占地按原表提供，均为 1 级，可直接搜索中文名；它们不支持绑定守军。编辑器仍以名称和色块示意，游戏内显示待接入关卡后验证。
3. 切换“选择”，拖动已有建筑；右侧可填写坐标和等级。
4. 左上角“城墙设置”选择 1～10 级，再点击“绘制城墙”。支持连续绘制、直线和矩形围墙。按住拖动绘制，建筑占用格会跳过；重复涂过旧墙可改变其等级。“统一修改全部城墙等级”可批量改级，支持撤销。“擦除”可清除墙和建筑。
5. 选中旗子或龙弹堡，点击“添加防守英雄”，设置英雄种类、等级和培养配置。
6. 检查无重叠和越界后，点击“导出布局”，将下载的 JSON 文件交给维护者接入关卡。

图中建筑是带名称的占地示意，尺寸来自原版数据。右侧参考图可放大，也可叠到画布中，调整透明度、大小和位置。初始是空白第七关，未采用此前被否定的估算布局。

## 防守英雄培养

每名守军独立配置。普通英雄可选择未转生、1 转和 2 转，对应三种实际形态；晋升等级强化当前形态。特殊英雄按原表提供选项，不套用普通英雄的形态规则。英雄等级单独设置为 1～100 级。

普通英雄的变异属性有水、火、风、雷、土五系，每系分 1～3 级，也可以选择“无变异”。原表未提供变异数据的英雄只显示“无变异”。

点击“添加技能”，从当前英雄的原版可学技能中选择，最多配置 3 个。每个技能单独设置等级，“技能升满”将已选技能升至原表上限。普通攻击自动保留；不配置培养技能时只使用普通攻击。技能固定保存，每次进场不重新随机。

选择技能后，下方显示原版中文说明、当前等级的效果数值、有效目标和满级状态。更换技能或调整等级时自动更新。详情来自游戏详情面板使用的 `info_skill` 和 `info_info_skill`，保留原表的数值和单位格式。

切换英雄会移除不兼容的技能，并将不支持的形态、晋升或变异恢复为默认值。操作可撤销。所有培养配置支持本机自动保存、导出和重新导入，旧布局中缺少的字段按未培养处理。已有 `skills` 字段会保留，不再在导入时丢失。

## 守军符文

选中旗子或龙弹堡，在对应守军的技能设置下方找到“嵌入符文”。每名守军有 5 个独立槽位，每槽可选勇气、迅猛、统御符文的 1～3 级，也可选择“不嵌入”。

展开该槽的“属性设置”，可添加基础、二转、三转属性，选择属性种类和原表数值，也可指定专属英雄。每一层同类属性只保留一条。属性需手动添加，未添加的属性不提供加成；这属于关卡编辑配置，不模拟符文自然生成的随机属性。专属属性和转生属性由原版组件按英雄条件生效。

面板下方预览组合技能名称、等级和说明。组合从槽位 1 开始连续匹配，空槽会中断；顺序与符文等级都会影响结果。符文组合技能与三个培养技能分开计算。原表缺少中文说明的组合会标明说明缺失。

符文设置可撤销，随草稿自动保存，也会随布局导入导出。旧文件未提供符文时保持未配置状态。单人关卡和侦察池共用接入编译器，会将符文转成原版 `eqp` 字段。编辑器与离线原函数核对已通过，游戏内实际效果需接入具体布局后复测。

## 保存和恢复

同一浏览器、同一入口会自动保存草稿。预览页面与双击文件属于不同入口，切换前应导出备份，再导入继续编辑。导出文件不包含参考图，只包含布局数据。

导入和新建也能撤销。浏览器无法保存时会显示备份提示。删除建筑会同时删除绑定的守军，撤销可以恢复。

快捷键：V 选择，W 画墙，E 擦除，H 平移；Delete 删除，Ctrl+Z 撤销，Ctrl+Y 重做。滚轮缩放，空格加拖动平移。方向键移动选中建筑，Shift 加方向键移动五格。

## 接入游戏

布局格式见 `analysis/rpc-contracts/pve-layout-editor.json`。先验证用户导出的文件：

```powershell
python tools/import_pve_layout.py <布局文件> --check
```

用户确认布局后写入契约与运行时注册表：

```powershell
python tools/import_pve_layout.py <布局文件> --apply
```

应用会保存 `analysis/rpc-contracts/pve-layouts/stage-<编号>.json`，更新 `native_boot.js` 的专用数据块。随后按原流程检查、构建、备份并覆盖安装。该命令不安装 APK、不修改设备存档，也不解锁关卡。

注册表为空时保持既有关卡布局。守军的稳定编号和旗子关联由工具生成。建筑战斗、原关卡掉落和玩家主城继续使用原有逻辑。编辑器显示原版 60 × 60 格地形，可建造区域为 X、Y 各 11～48；64 × 64 仅为旧 JSON 元数据。

## 维护与验证

```powershell
python tools/build_layout_editor.py
node analysis/check_layout_editor.cjs
node analysis/check_layout_runes.cjs
python analysis/check_layout_editor.py
node analysis/check_layout_editor_browser.cjs
```

刷新陷阱目录时，先运行 `node tools/build_layout_trap_catalog.cjs`，再构建 HTML。陷阱名称、占地和等级来自原版 `unit_main` 与 `string_data`，排除无等级占位条目和同名移动单位。

刷新植物、石头和生物目录时，先运行 `node tools/build_layout_decoration_catalog.cjs`，再构建 HTML。该脚本只刷新原表 `first_type=4` 的对象，不改已有建筑或守军目录。

刷新符文目录时，先运行 `python tools/extract_layout_runes.py` 提取原表和装备函数，再运行 `node tools/build_layout_rune_catalog.cjs`，最后构建 HTML。目录还复用已有的 `item`、`skill_data` 和完整 `string_data` 本地提取。原始输出只放 `.local/layout-editor/runes/`。

浏览器检查使用 `.local/layout-editor/qa/node_modules/playwright` 和本机 Chrome。运行记录、临时浏览器资料与截图仅放 `.local/layout-editor/`。源目录数据来自原包 `unit_main` 与 `string_data`，排除了等级为空的施工占位类型。

培养目录来自原版 `unit_main`、`unit_battle`、`hero_to_skill`、`skill_to_hero`、`skill_data` 和 `mutate_effect`。技能详情还使用 `string_data`、`info_skill` 和 `info_info_skill`。先运行 `python tools/extract_layout_skill_info.py` 提取详情表，再运行 `node tools/build_layout_guard_catalog.cjs` 刷新目录，最后重新构建 HTML。接入工具根据形态和晋升解析实际 `typeid`，按变异配置保留原版普通攻击，并验证技能兼容性和等级。不写移动英雄的 `x/y`。

刷新玩家规则时，先运行 `python analysis/inspect_layout_player_limits.py` 只读实例 1 存档并恢复原表，再运行 `node tools/build_layout_player_rules.cjs`，最后构建 HTML。规则保存到 `analysis/layout-editor/player-rules.json`，原始输出仅放 `.local/layout-player-mode/`。新增验证命令为 `node analysis/check_layout_player_mode.cjs`、`node analysis/check_layout_player_mode_browser.cjs`、`python analysis/check_layout_player_mode.py`（后者使用前一项生成的浏览器导出文件）。
