# 布局编辑器设计规范

## Stack

原生 HTML、CSS、JavaScript。无外部依赖。源文件位于 `analysis/layout-editor/`，构建工具打包为 `artifacts/关卡布局编辑器.html`。按项目文件规则，本设计文档放在 docs 下。

## Tokens

中性白色控制区，深色正文，低饱和紫色作为选中和主操作色。地图用浅绿底色。颜色统一为 CSS OKLCH 变量。基础间距 4、8、12、16、24，控件圆角 6，面板圆角 10。

## 布局

顶部为关卡信息和导入／导出。左侧建筑选择，中间为等距画布，右侧属性、验证和参考图。窄屏将属性移到画布下方，手机将素材栏改为横向排列。文字与控件均使用系统中文字体。

## Components

- `index.html`：工具栏、建筑面板、画布、属性面板、参考图和说明弹窗。
- `editor.css`：样式令牌、交互状态、响应式布局和减少动态效果规则。
- `core.js`：布局格式、碰撞验证、格子换算、导入和导出。
- `editor.js`：交互、撤销、自动保存、拖放和 SVG 渲染。

## Decisions

2026-10-19：按原版 `world1.tmx` 统一地图边界。60×60 格地形用灰色底，11～48 的可建造格用绿色底与绿色边框。操作提示持续显示有效坐标；完整建筑占地、墙及属性输入均限制在有效范围。边界配置从 `analysis/rpc-contracts/layout-map.json` 注入单文件 HTML，JS、Python 与侦察池共用。旧 JSON 的 64×64 元数据继续兼容。

2026-10-15：用户反馈城墙设置缺失。将城墙等级和绘制方式固定放在素材栏顶部，选中建筑时仍可访问；增加直线、矩形围墙和全部城墙统一改级。右侧在画墙模式显示当前设置说明。

2026-10-15：实现用户确认的离线编辑方式。初始为空白第七关，不默认采用用户已否定的估算布局。原版建筑占地和可用等级写入目录数据。无异步网络加载，因此不使用骨架屏。空画布提供放置提示，任何数据文件错误均保留原布局。

2026-10-19：防守英雄沿用属性面板的原生表单。转生／晋升、变异属性／等级各用两列展示；技能逐条选择并独立改级。特殊英雄只显示原表支持的培养选项，所有修改使用统一撤销和保存流程。

2026-10-19：技能条目下方直接展示说明、属性键值和目标信息，随技能与等级切换更新。沿用现有明亮属性面板，避免悬浮详情遮挡技能选择。

2026-10-19：素材栏顶部增加编辑模式和玩家大本营等级，沿用原生 select 与既有表单间距。玩家素材条目在名称下显示配额和最高等级，禁用条目保持可读。城墙标题显示配额；超限旧布局保留并由既有检查区列出错误，不增加自动删除步骤。
