# 单个问题的短交接模板

每个问题只保留必要结论，建议控制在一页内。放入 `analysis/evidence/<问题名>.md`，原始运行输出放 `.local/<任务名>/`。持久且必要的证据可筛选后纳入 evidence，避免结论只依赖临时文件。

```markdown
# 问题名称

状态：用户确认 / 离线通过待复测 / 未解决。

触发：具体操作和出现的问题。
根因：已证明的参数、字段或状态条件；未证明时标为假设。
证据：原版函数或契约路径、函数名；运行记录路径和关键字段。
修改：文件和函数，以及行为变化。
验证：运行的检查命令和结果，人工复测单独写。
待办：尚未验证的条件；下一步只做哪一项。
```

不要复制完整日志、反汇编或长期交接。旧假设失效时注明原因和新证据，避免下轮重复尝试。
