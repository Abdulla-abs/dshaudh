# 布局编辑器守军培养

状态：离线和浏览器检查通过，游戏实战待复测。

触发：防守英雄只能设置种类和等级，无法选择技能、转生和变异。

根因：`editor.js` 缺少培养控件；`core.js` 导入时只保留基础字段，丢弃已有技能。接入工具将英雄形态和变异固定为初始值，原技能检查只验证数值范围。

原代码证据：目录由原版 `unit_main`、`unit_battle`、`hero_to_skill`、`skill_to_hero`、`skill_data` 和 `mutate_effect` 生成。普通英雄有三种实际模型，各自有晋升链。欧瑟、奎克、拉比克和雷克斯只有一种模型，普通攻击表也未提供变异索引。不能按 `origin_typeid` 的数量推断模型数量。

修改：每名守军可独立选择转生形态、晋升、变异属性和等级，以及最多 3 个固定技能及技能等级。技能列表按英雄筛选，禁止重复技能族。支持移除技能和一键升满已选技能。切换英雄时清理不兼容配置，操作可撤销。导入保留可选培养字段，缺省字段兼容旧布局。

接入：`tools/import_pve_layout.py` 根据目录解析实际 `typeid`、`unit_level`、`unit_mutateid` 和对应普通攻击。技能与培养校验和编辑器一致，继续由 `did` 绑定建筑，不写移动英雄的 `x/y`。

验证：核心 JavaScript、Python 的 6 项检查和真实 Chrome 浏览器检查通过。Python 遍历全部英雄形态、晋升和变异组合，对缺少原版数据的组合验证拒绝。浏览器实际操作验证技能选择、升级、满级、移除、重复限制、切换英雄、撤销、自动保存、导出与重新导入，并检查窄屏无横向溢出。第 7、16 关旧布局和浏览器新导出文件均通过接入校验。原版守军创建检查通过。

运行记录与截图：`.local/layout-editor/browser/guard-cultivation-desktop.png`、`guard-cultivation-mobile.png`、`exported-stage7.json`。单文件交付件已重新构建为 `artifacts/关卡布局编辑器.html`。

2026-10-19 技能详情补充：按用户截图增加随技能和等级更新的中文说明、属性、有效目标、无效目标和满级状态。原版 `SkillInfo.setName/setAttribute/setValidTarget` 分别使用 `skill_data`、`string_data`、`info_skill`、`info_info_skill`。详情目录沿用这些表，不从战斗内部字段推算展示数值。
