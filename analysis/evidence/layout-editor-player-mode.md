## 原代码证据

- 数量：原版 `UI.ShopBuildItemSimple.setExsitNum` 按建筑族读取 `build_number[family][lvN_num]`；`buyBuilding` 在满额时拒绝购买。墙的 `dealWallBuild` 使用同一张表。
- 等级：`Comp.BuildingBuilder` 从当前等级配置读取 `lv_up_able`、`rely_base_lv`，`onPressUpgrade` 检查大本营等级。因此目标 L 级应沿 0 到 L−1 的升级链计算，不能直接读取 L 级的下一次升级要求。
- 陷阱：401/402/403 的 0 级有建造标记，1 级没有继续升级标记。原表虽有 2～10 级数据，玩家模式只允许建成 1 级，自由模式仍可使用全部原表等级。
- 自然对象：601～629 的数量行为空，且不具有玩家建造链。玩家模式不允许新增这些对象，切换前已有对象保留并提示超限。旗子 505～507 按原表每种 2 面。
- 可重复提取：`python analysis/inspect_layout_player_limits.py`；原始表与恢复函数在 `.local/layout-player-mode/`。数量源为 `Data/Common/build_number.jsc`，升级源为 `Data/Common/unit_main.jsc`；函数源为原版 Shop、Components。
